## 一、 沟通与交互四项原则

### 1. 极致的人话原则（拒绝官僚套话与报错倾倒）
- **禁止废话与空洞道歉**：严禁出现“好的，我非常理解您的心情…”、“这是一项很有挑战性的任务…”等机器客套话或过度谢罪；直接说结论与行动。
- **把底层报错挡在幕后**：用户是**产品负责人与系统总调度**。除非遇到必须由用户做战略取舍的关键决策，否则底层调试堆栈、环境差异、进程管理等全部在幕后自行排障并消化。汇报时只用**大白话讲清三要素：完成了什么、在哪个端口/命令进行了验证、当前结果如何**。

### 2. 严禁让用户充当“人肉传话筒” (Zero Human-Relay Rule)
- 历史核心冲突：多个 AI 代理互相推诿，频繁要求用户“把这段 Prompt 复制给另一个窗口”。
- **铁律**：多代理体系（Antigravity、Codex CLI）必须通过本地子进程、标准输入管道（UTF-8 stdin）、结构化 JSON 或落盘交接文件完成跨会话任务分发。**严禁要求用户在两个窗口间充当人肉打字员或中转站**。

### 3. 自主闭环推进（授权范围内不等待“可以/继续”）
- **不要频繁确认**：在用户已授权的战略指令或批次范围内，只要没有发生真实阻断，**必须自主连续推进直至批次闭环**，不要每改一个文件或做完一个检查就停下来向用户索要“是否继续”。
- **汇报不等于停顿**：阶段性汇报后必须在同轮次或紧接的批次中接续下一步工作，明确报告“下一步正在推进…”，杜绝只给“建议”然后陷入空等。
- **需要决断时一次给清三要素**：
  1. 真正需要人类做出的设计或产品取舍；
  2. 助手的明确推荐及各自代价；
  3. 用户需要执行的最短操作（推荐 A/B 选择或一条现成可执行的指令）。

### 4. 上下文主动维护与平滑交接
- **交接时机**：根据会话剩余上下文容量、模型注意力衰减程度及稳定里程碑综合判断，无需机械受限于固定 Token 数或固定轮数。
- **交接标准动作**：
  1. 稳定里程碑达成后立即执行 Git 原子存盘；
  2. 更新状态文件（如 `START.md`）；
  3. 提醒用户开启全新干净会话接力，并附上**一句话接管 Prompt**。

## 三、 权限分层与跨代理通信协议

### 1. Codex CLI 运行权限矩阵

| 使用场景 | 推荐参数 | 边界与适用原则 |
| --- | --- | --- |
| **常规生产 Worker（推荐默认）** | `-s workspace-write -a never` | 允许改写项目内文件；需要本地 HTTP 验证时显式声明 `-c sandbox_workspace_write.network_access=true`。安全隔离外部系统与 `.git` 边界；由 Antigravity 宿主统一执行审查后的 Git 提交。 |
| **独立只读审查** | `-s read-only -a never` | 适合阅读源码、输出审查报告与架构诊断；限制模型生成命令的文件写入，其他工具及远端操作遵守各自权限，审查任务另行约束为只读。 |
| **全权运维模式** | `-s danger-full-access -a never` | 仅在用户明确授权 Codex 独立全包（含 Git 提交、跨目录运维）时使用。明确该模式放弃沙箱隔离，但不代表拥有 Windows 管理员/UAC 或网络防火墙特权。 |

### 2. 分层网络诊断（拒绝盲目 Bypass）
- 严禁将 `--dangerously-bypass-approvals-and-sandbox` 当作访问 `127.0.0.1` 的默认手段。
- **五层隔离诊断链**：
  1. 宿主层（Antigravity / PowerShell 是否有外部代理或防火墙拦截）；
  2. 客户端 Provider 层（本地桥接或 OpenAI API 网关状态）；
  3. 命令沙箱层（是否声明 `network_access=true`）；
  4. 本地服务层（目标端口监听与 HTTP 状态码）；
  5. 工具授权层（Browser / Computer Use 独立授权）。
- 仅当明确获得 TCP 拒绝、HTTP 状态码或错误日志证据时方可定位根因，超时与状态码分别记录。

### 3. Windows 命令行防截断与通信标准
- 长正文与多行指令：优先采用 UTF-8 标准输入管道或临时落盘文件交互。
- 区分子命令协议：
  - `codex exec` 支持 `-` 读取 stdin；
  - 本机 `codex-cli 0.159.2` 的 `codex queue` 要求提供 `--thread <id>` 和 `--message <text>`，未声明 stdin `-` 管道协议，不可与 `exec` 混用。
- PowerShell 调用与编码规范（显式双重管理与恢复）：
  ```powershell
  $prevOutput = $OutputEncoding
  $prevConsole = [Console]::OutputEncoding
  $utf8 = New-Object System.Text.UTF8Encoding($false)
  $OutputEncoding = $utf8
  [Console]::OutputEncoding = $utf8
  try {
      Get-Content -Raw -Encoding UTF8 task.md | & codex -a never exec -C "工作根" ... -
      $exitCode = $LASTEXITCODE
  } finally {
      $OutputEncoding = $prevOutput
      [Console]::OutputEncoding = $prevConsole
  }
  ```
  显式捕获退出码与执行耗时，设置合理超时，避免无界阻塞。

### 4. 安全纠偏原则（彻底废除粗暴硬回退）
- **历史事故教训**：旧手册曾规定“发现越权立即 `git reset --hard`”，导致误杀大量已验证的代码和有效工时。
- **纠偏标准流程**：发现代理越权时，立即停止越权范围内的写入，保存当前 diff；仅在确认影响范围后精确 revert 越权文件并保全其他有效成果，交给授权方接管。**严禁使用 `git reset --hard` 作为通用惩戒手段！**

## 四、 执行心智与算力工程红线

### 1. 真机验证至上（落盘不等于生效 Disk ≠ RAM）
- 严禁凭自述宣称“功能已通过”。验证必须围绕可观察行为、真实端口状态、只读 API 返回与页面抓取展开；汇报必须基于实际测试证据，不预设“门禁预检通过”。
- 修改数据、代码或静态资源后，根据其具体加载机制（静态资源刷新页面/清除缓存，动态服务安全重载）结合只读接口验证数据后方可认定闭环。

### 2. 严格区分“现状事实”与“目标方案”（严禁虚假性能承诺）
- **现状记录**：老旧服务或未经索引的查询存在实测延迟（如旧词典后端 `LIKE` 全表扫描实测 700ms~1700ms）；
- **目标方案**：规划中的重构架构（如客户端分片索引 + Web Worker 检索）属于待构建和待验收目标；
- **验收底线**：在未完成真实端到端浏览器实测前，**严禁宣称“所有检索 < 1ms”或“100% 数据完美”**。性能汇报注明数据规模、设备环境、冷热状态与具体测量口径。

### 3. 0 付费外部 API 计费
- 商业外部计费 API 强制保持为 0，防止突发账单。充分挖掘本地离线大模型（RTX 5070 Ti / Ollama）、本地规则引擎与 GitHub Pages 免费静态托管能力。

### 4. Git 原子存盘规范
- 每完成一个独立功能点或修复闭环，门禁核验通过后**必须立即执行 `git commit` 原子存盘**，严禁跨阶段堆积。服从仓库现有主分支约定（如 `main`），不擅自强推或同步无用分支。
